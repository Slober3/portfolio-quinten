## Het gevaar van 'klikkende beheerders'

Zodra je meer dan één Windows-server of Active Directory-domein beheert, leidt handmatig configureren via GUI-wizards tot stille *configuration drift*. Een vergeten DNS-record of afwijkend GPO-recht merk je pas tijdens een incident. Door **Systems as Code** te combineren met **Pester** krijgen infrastructuurwijzigingen dezelfde automatische controle als softwarecode.

## Minimale Pester-validatie voor AD & DNS

Hieronder een compact voorbeeld uit mijn *Pester-Test-Examples* repository (`Slober3`) waarmee studenten meteen controleren of kritieke diensten actief en resolvable zijn:

```powershell
Describe 'Core Infrastructure Baseline' {
  It 'Active Directory Domain Services service is running' {
    $svc = Get-Service -Name 'NTDS' -ErrorAction SilentlyContinue
    $svc | Should -Not -BeNullOrEmpty
    $svc.Status | Should -Be 'Running'
  }

  It 'Internal DNS resolves expected gateway record' {
    $res = Resolve-DnsName -Name 'gw.lab.local' -Type A -ErrorAction SilentlyContinue
    $res.IPAddress | Should -Contain '10.10.1.1'
  }
}
```

Door na elke lab-deployment automatisch `Invoke-Pester` te draaien, verschuift beheer van gokken naar aantoonbare precisie.
